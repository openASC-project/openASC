# Content formats

This is the compatibility record for the current implementation. Planned work is separate from verified behavior. A limited independent keyboard-driving prototype is locally tested; original physics and general gameplay compatibility are not established.

Actual successful texture uploads are counted in the browser inspector. `original_shaders` remains false; server metadata alone does not prove GPU rendering.

## Native KN5 and GPU path

### Native configuration and composition

`asc-config` reads UTF-8 INI/LUT with optional BOM, source lines, case-normalised section/key identifiers, strict duplicate/quote checks, literal backslashes and comments outside quotes. Input is limited to 4 MiB and 100000 nonempty records. LUT x values must strictly increase; values/samples must be finite. Piecewise linear interpolation clamps endpoints and rejects numeric overflow. Native legacy encodings, includes and expressions are unsupported.

`asc-scene` accepts an explicit models.ini or models_LAYOUT.ini path. It loads static MODEL_n declarations in source order, requires explicit FILE/POSITION/ROTATION, applies translations to geometry/draw centres and ROAD/visible bounds, and rebases indices/materials. Nonzero model rotations fail until the original convention is validated. Absolute, drive-relative, stream, parent-traversal and resolved-outside-root paths are rejected on every host. Invalid static declarations/resources fail the scene rather than silently presenting a partial load. Dynamic sections and unknown keys produce omission warnings.

Composition limits are 256 models, 256 MiB of combined render buffers, 32 MiB of retained model metadata text, 200000 nodes and 100000 materials/textures. One separately bounded KN5 is decoded before the aggregate limit is checked; peak CPU memory can include that in-flight model. Each model keeps its own embedded texture namespace and original file offsets; source (128 MiB), retained texture storage (256 MiB) and upload payload (256 MiB) budgets are shared across the scene. Repeated references currently duplicate model/texture resources. Original shared/cross-model lookup precedence remains unvalidated. Composed summary version 0 marks an aggregate; individual model versions remain in the manifest. No scene model or texture extraction is performed.

The native Rust reader directly consumes one KN5 v5/v6 with no Python runtime. It validates UTF-8, finite numeric fields, boolean fields, affine/composed transforms, material/index references and unexplained trailing data. Structural budgets are 2 GiB per file, 1 MiB per string/32 MiB combined strings, 100000 textures, 10000 materials, 100000 combined properties/mappings each, 200000 nodes and 128 hierarchy depth. Per mesh, at most 2000000 vertices and 12000000 triangle indices are accepted; source geometry and flattened render buffers each have a separate 256 MiB budget. Texture bodies are skipped in place. Skinned geometry is structurally validated but not drawn.

The native renderer draws active visible renderable static indexed meshes with near LOD start at or below zero. World transforms use the same independently tested flat column-major convention as the Python path. UVs survive unchanged. Normals use the inverse-transpose linear transform and normalisation; a singular transform is diagnosed and uses geometric lighting. An upright isometric orthographic camera fits active near-level ROAD geometry when present, otherwise visible geometry. Original indices keep their winding; rendering is double-sided. It writes an sRGB frame and unpads a bounded 256-byte-aligned GPU readback. Library capture dimensions are limited to 1..4096 per axis; the CLI uses 1240 by 900. An explicitly requested new PNG is the only content-derived output file. There is no texture extraction, native driving loop or original shader/physics claim. Native window inspection is a separate command sharing this render pass.

## Native diffuse textures and material states

Native structural inspection retains embedded texture ranges without reading their payloads. Rendering resolves exactly one txDiffuse mapping per used material to exactly one active embedded name, compared without ASCII case. Duplicate names/references, inactive entries, malformed DDS, I/O and budget failures are diagnosed and use per-material diagnostic colours. Resource successes and failures are cached by descriptor. The input file remains unchanged. External skin textures are not loaded.

The Rust decoder supports BC1/2/3 and mask-defined 8/16/24/32-bit luminance or 16/24/32-bit RGB, with explicit alpha masks and validated pitch. Dimensions are at most 8192 per axis and 16777216 pixels. Scene budgets are 128 MiB source bytes, 256 MiB retained CPU texture storage and 256 MiB GPU upload payload. BC blocks count at their encoded size; software-decoded pixels count at full RGBA mip size. Limits are checked before allocation/upload. GPU payload counters exclude driver alignment/overhead and the small diagnostic fallback texture; they are not total VRAM measurements. Required masks must be contiguous, in range and nonoverlapping. Cube/volume/DX10/BC4-7/premultiplied variants remain unsupported. The implementation follows the primary [DDS layout guide](https://learn.microsoft.com/en-us/windows/win32/direct3ddds/dx-graphics-dds-pguide) and [block compression description](https://learn.microsoft.com/en-us/windows/win32/direct3d10/d3d10-graphics-programming-guide-resources-block-compression), with original decoder code and fixtures.

Authored compressed and raw mip chains are retained. Raw lower levels accept exact tightly packed or exact DWORD-aligned storage; other/ambiguous layouts fail rather than being guessed. Raw base-only textures receive a generated chain using independent linear-sRGB colour/straight-alpha box averaging, including odd edges. This is approximate generated filtering, not original-game parity. The CLI retains validated BC1/2/3 DDS blocks when base dimensions are block-aligned, requests TEXTURE_COMPRESSION_BC only if the selected adapter supports it, and uploads authored levels as BC1/2/3 sRGB. Small mip tails use physical block extents and block-row pitches. Raw and unaligned images use RGBA8 sRGB. Without the device feature, retained BC sources decode one at a time within the remaining upload budget; excess resources use diagnostic colours. Use --rgba-textures to disable the feature and exercise that fallback. Repeat addressing, trilinear filtering and linear alpha remain in use. Per-resource metadata decoded_bytes describes the potential RGBA chain size, not an allocation for retained BC data. Explicit library load_textures/load_track_textures remain CPU RGBA readers; prepare_textures/prepare_track_textures select the encoded-capable path. Feature negotiation follows the [wgpu compression feature contract](https://docs.rs/wgpu/30.0.1/wgpu/struct.Features.html#associatedconstant.TEXTURE_COMPRESSION_BC). Original shader/material behavior is still unimplemented.

Material preview uses the recorded alpha-test flag or blend mode 2 for a 0.5 cutoff, blend mode 1 for straight-alpha blending, and ignores texture alpha on opaque draws. The alpha property is clamped to 0..1 and ksDiffuse to 0..2 for basic directional lighting. Depth mode 0 uses less-or-equal and writes depth; mode 1 is read-only with a small negative constant/slope bias; mode 2 is always-pass/read-only. Unknown blend/depth values use an opaque depth-writing fallback with a structural diagnostic. Opaque groups precede transparent draws; transparent meshes use stable back-to-front camera-depth sorting of mesh centres. This is approximate mesh sorting rather than per-pixel transparency.

`--diagnostic` skips texture loading while retaining material-state preview. Rendering reports `native_static_diffuse_preview` or `native_static_material_diagnostics`, actual uploaded textures, textured/cutout/blended draw counts, and resource diagnostics. Original shaders, multilayer/detail/normal material effects, alpha-to-coverage, shadows and validated colour/lighting behavior remain unsupported. Drift grass has visible white/stippled artifacts; a textured frame is not evidence of original visual parity.

## Native window and camera

The `view` command uses winit 0.30 and wgpu 30 to present a persistent GPU scene on an SDR RGBA8/BGRA8 surface. It selects an sRGB view format and converts BGRA readback to canonical RGBA before PNG encoding. Geometry, texture and material resources survive camera changes and ordinary resize. A bounded orbit camera supports perspective/orthographic projection, pan, zoom and near-top view. Mouse button/cursor state clears on focus loss, cursor exit and resize. The app waits when idle and skips zero-size/occluded views.

Window and offscreen paths share shader/pipeline preparation, scene drawing and aligned readback. Window draws re-sort transparency using current camera direction. T changes diffuse RGB without removing loaded alpha cutouts; report diffuse_enabled/textured_draws describe the current RGB mode. The initial client is 1240 by 900 physical pixels and size is bounded to 4096 per axis. Optional `--capture NEW.png` saves the first actual surface frame; `--captures DIR` enables F12 snapshots. Overwrite refusal is retained. Driver surface COPY_SRC support is required only for these captures and the explicit window test.

Outdated/suboptimal surfaces are reconfigured and lost surfaces have at most three recreation attempts. Timeouts have bounded redraw attempts before waiting for further interaction. Unsupported SDR formats, validation errors and capture failures remain explicit. These paths are implemented, not a claim of tested monitor/adapter migration, OS suspend/minimise behavior, mobile support, HDR, device-loss recovery or original game UI compatibility. Native vehicle simulation/FFB remain unimplemented.

## INI subset

- UTF-8 with optional BOM by default; legacy encodings require an explicit selection.
- Section headers and keys are normalized to uppercase; values remain strings.
- Keys are split from values at the first equals sign. Empty values are supported.
- Blank lines and full-line semicolon, hash, or double-slash comments are ignored.
- Semicolons begin inline comments outside double-quoted values.
- Whole values may be double-quoted. Backslashes remain literal, without escape processing.
- Duplicate sections and duplicate keys, including case variants, are errors rather than silently merged values.
- Keys before a section, malformed headers, bare lines, and malformed quotes are errors.

This strict subset deliberately rejects ambiguous input. It does not claim the original game's complete parser behavior. Section and key source lines are retained in the Python API and diagnostics.

## LUT subset

Rows contain exactly two finite numeric values separated by a vertical bar. The following is an original example:

```text
0|10
10|30
```

The x coordinates must be strictly increasing. Duplicate or descending coordinates, empty tables, extra columns, NaN, and infinity are errors. Scientific notation and a single-point constant table are supported. Comments follow the same rules as the INI reader.

Sampling uses piecewise linear interpolation. The example returns 20 at x=5. Samples outside the domain return the nearest endpoint value. This interpolation policy belongs to openASC's current reader; equivalence to every original game subsystem is not claimed. Extreme numeric ranges that cannot be interpolated reliably are diagnosed.

## Static track configuration

The scene inspector selects `content/tracks/TRACK/models.ini`, or `models_LAYOUT.ini` when a layout is provided. It requires explicit file, position, and rotation fields in each numbered MODEL section.

Model paths may use forward or backslashes, but must resolve within the selected track folder. Absolute paths, Windows drive-relative paths, parent escapes, and resolved links outside that root are rejected. Vectors require three finite numbers. Values are recorded without interpreting rotation units or applying transforms yet.

Unknown sections and model keys are warnings. Missing resources, invalid transforms, and unsupported KN5 headers are errors. Errors in one model do not suppress diagnostics for the other model declarations. If no model passes inspection, the report also includes `no_models`.

## KN5 headers and static geometry

Local observations confirm the six-byte `sc6969` signature followed by a little-endian 32-bit version. Version 6 includes another 32-bit header field. The lightweight scene inspector accepts versions 5 and 6, checks header length, and records file size. It does not validate the remaining structure; a header-only fixture can pass that limited inspection. The separate KN5 reader parses the supported remaining structure and rejects unexplained trailing bytes.

The binary reader handles length-prefixed UTF-8 names, embedded texture descriptors and payload skipping, material properties and sampler mappings, transform nodes, and static triangle meshes. Static vertices contain position, normal, UV, and tangent fields in 44 bytes; indices are 16-bit. Material references and index ranges are checked. Skinned node records are consumed to preserve stream alignment, but their geometry is explicitly omitted from the preview.

The renderer applies node hierarchy transforms and model translations, and samples supported embedded txDiffuse textures with basic lighting. It uses a fixed 0.5 cutoff for alpha-tested/alpha-to-coverage materials, approximate mesh-sorted straight-alpha blending, recorded depth modes, and a small read-only overlay bias. Geometry remains double-sided. Original shader behavior, multilayer/detail/normal maps, shadows, and exact distance-based LOD are not reproduced. Hidden/inactive/non-renderable/empty and later-LOD meshes are omitted with a diagnostic. Nonzero model-level rotations are diagnosed and skipped rather than assigned an unverified Euler convention.

Malformed signatures, versions, truncated fields, invalid flags, unknown node types, invalid indices/material references, nonfinite geometry, non-affine transforms, and numeric overflow produce errors with byte offsets. The reader limits files to 2 GiB, total geometry to 256 MiB, combined string bytes to 32 MiB, nodes to 200000, and hierarchy depth to 128. The assembled local preview additionally limits geometry to 384 MiB. These are current implementation limits, not original engine limits.

Primary implementation references used to check field layouts are [AcTools Kn5Basic](https://github.com/gro-ove/actools/blob/master/AcTools/Kn5File/Kn5Basic.cs) and [kn5-converter](https://github.com/RaduMC/kn5-converter/blob/master/kn5%20converter/Program.cs). The openASC parser, bounds calculations, diagnostics, renderer, and fixtures are independently written. No source files from these tools are bundled.

## Embedded DDS preview

The KN5 importer records texture offsets without extracting payloads. The local viewer resolves a unique active embedded txDiffuse reference for each material, case-insensitively within that model. External texture files and ambiguous embedded names are not guessed. Unsupported or missing resources fall back to diagnostic material colours with warnings.

The supported legacy DDS subset includes DXT1/BC1, DXT3/BC2, DXT5/BC3, mask-defined RGB at 16/24/32 bits, and luminance at 8/16/24/32 bits with optional alpha. Channel masks must be contiguous, in range, and nonoverlapping. The reader validates dimensions, surface kind, declared compressed mip-chain lengths, and uncompressed base row pitch. A declared linear size is not treated as raw row pitch. Cube/volume resources, DX10 headers, BC4-7, premultiplied DXT2/4, and other formats are explicitly unsupported.

Compressed authored mip chains are preserved for upload. Raw textures use their validated base image and GPU-generated mipmaps; lower raw authored mips are not interpreted or validated. The upload payload contains only the retained subset, not a guaranteed complete DDS export. UVs and image row order are passed through without an additional flip.

WebGL uses S3TC when available and compatible with mip dimensions. Otherwise, original JavaScript decodes BC1/2/3 or raw pixels to RGBA. Compressed upload failure also attempts the bounded software path. Alpha indices, endpoint interpolation, cropped blocks, channel masks, padded row order, and both BC3 interpolation branches have original pixel tests. Software rounding may differ slightly from a GPU implementation.

DDS limits are 8192 pixels per axis, 16777216 base pixels, and 128 MiB per embedded source. Per-scene retained texture data is capped at 128 MiB, with a 256 MiB RGBA mip budget covering the software path. These are preview limits. A failed GPU upload is reported in the browser, and never counted as a successful upload.

Opaque materials ignore texture alpha. Material transparency uses the recorded opaque/alpha-blend states; alpha-to-coverage uses a cutoff approximation. Depth modes map to normal, read-only, and disabled depth tests. Mesh-centre sorting does not solve intersecting transparent geometry. Grass and other multilayer materials can look white or otherwise incorrect when only their base map is shown. No shader or material parity is claimed.

The independent DDS implementation was checked against the primary Microsoft documentation for [DDS headers](https://learn.microsoft.com/en-us/windows/win32/direct3ddds/dds-header), [pixel formats](https://learn.microsoft.com/en-us/windows/win32/direct3ddds/dds-pixelformat), and [block compression](https://learn.microsoft.com/en-us/windows/win32/direct3d10/d3d10-graphics-programming-guide-resources-block-compression). Recorded state names are cross-checked against AcTools [blend](https://github.com/gro-ove/actools/blob/master/AcTools/Kn5File/Kn5MaterialBlendMode.cs) and [depth](https://github.com/gro-ove/actools/blob/master/AcTools/Kn5File/Kn5MaterialDepthMode.cs) definitions. No third-party decoder source is bundled.

## Surface definitions and ground support

The `ground` command reports `static_ground_query`, independently of the rendering preview. It reads `system/data/surfaces.ini` and then `content/tracks/TRACK/data/surfaces.ini`. With a layout, the second path is `content/tracks/TRACK/LAYOUT/data/surfaces.ini`; the base track file is not used as a fallback. Same-KEY track definitions completely replace system definitions. Missing files produce warnings; no available definitions produce an error. An invalid selected file fails loading instead of silently falling back to a system coefficient. This explicit policy is tested, but equivalence to every original loader precedence rule is not established.

Numbered SURFACE sections require KEY, FRICTION, DAMPING, IS_VALID_TRACK and IS_PITLANE. Keys are normalized to uppercase ASCII identifiers. Friction and damping must be finite and nonnegative; the two flags must be 0 or 1. Other known numeric fields are validated as finite metadata. Sound/FFB references and unknown fields are retained without execution; unknown fields/sections produce warnings. Duplicate keys within one file are errors, with the original source and line preserved.

The supported physical naming subset requires a leading decimal integer greater than zero, including zero-padded names such as `01ROAD`. Exactly one configured surface KEY must prefix the remaining mesh name. Missing or ambiguous matches are diagnosed and omitted; no guessed friction is substituted. Names containing WALL are omitted from the vertical probe and collected into a separate static collider when requested by ground --walls or drive. This conservative prefix policy is openASC behavior, rather than a claim to reproduce all original name matching. Naming and default-surface locations were cross-checked against the author-maintained [track construction guide](https://assettocorsamods.net/threads/build-your-first-track-basic-guide.12/) and the local installation.

Active supported physical meshes are included even when hidden or non-renderable. Inactive, empty, later-LOD and skinned geometry are omitted. Node transforms and model translations are applied; nonzero model rotations are diagnosed and omitted. The loader retains up to 1000000 input triangles across models, including subsequently discarded degenerate faces, with world coordinates bounded to +/-10000000 metres. These are current openASC limits. The geometric query builds a median BVH and retains double-precision transformed positions. Faces whose XZ projected area is at most `1e-12 * max(1, projected edge length product)` are excluded as vertical or degenerate.

A probe accepts a finite X/Y/Z origin and nonnegative finite maximum distance, within the same 10000000 metre range. It returns the nearest double-sided triangle below the origin, its geometric height, upward unit normal, mesh/model identity and source surface definition. Multiple road levels are queried relative to the origin, so a bridge above it is not chosen. Shared edges are included with numeric tolerance; equal-height ties use original triangle order. Distance/height comparisons use a 0.0000001 metre tolerance, and barycentric comparisons use a 0.000000001 tolerance. A miss returns null. Invalid query input is an error; a miss alone is not.

This query is geometric preparation for wheel support. It does not implement rigid-body collision, walls, suspension, tyre forces, procedural sinusoidal bumps, surface sound, dirt accumulation, penalties or FFB. Recorded friction/damping and validity/pit flags are metadata for later systems. The rendering viewer's ROAD-name focus button remains a separate bounding-box heuristic.

## Packed and unpacked vehicle configuration

The `car` command uses `vehicle_configuration_subset`, with `simulation_ready: false`. It selects `content/cars/CAR/data/` if present, otherwise `data.acd`, unless an explicit packed/unpacked source is requested. Selection applies to the complete source, with no per-file fallback. Data references use flat case-insensitive ASCII filenames. Directory entries that collide case-insensitively are rejected, and resolved file links must stay inside the selected data directory. Referenced visual models must stay inside the car directory. Text decoding is UTF-8 with optional BOM by default, or an explicitly selected encoding.

Ordinary ACD records contain little-endian signed lengths, a plain ASCII filename and an encoded payload with one relevant byte per four stored bytes. The optional -1111 prefix and following word are retained; the extra word's semantics and the other three payload bytes are not interpreted. Eight legacy checksums of the lowercase ASCII folder identifier produce the decimal ASCII key; subtraction modulo 256 restarts at each entry. Indexing validates the complete archive structure before any entry is read. Truncated fields, unsafe/duplicate names, invalid counts and budget violations are errors with byte offsets. There is no authenticated integrity check, so a different folder key is not guaranteed to produce a dedicated wrong-key error; downstream text/config validation still applies. Nonstandard/protected variants are not guessed. The reader has no extraction or writing API.

Limits are 64 MiB per archive, 4096 records, 255 filename bytes, 8 MiB per decoded entry and 16 MiB combined declared decoded data. Folder key identifiers support 1–128 ASCII letters, digits, underscores and hyphens. Unpacked selected files use the same per-file and loaded-data budgets. Archive layout and checksum behavior were cross-checked against primary implementations in [AcTools AcdReader](https://github.com/gro-ove/actools/blob/master/AcTools/AcdFile/AcdReader.cs) and [AssettoTools ACDEncryption](https://github.com/0danny/AssettoTools/blob/master/ACDBackend/ACDEncryption.cs). The bounded index, car source abstraction, diagnostics and tests are original code; no third-party implementation is bundled.

The vehicle subset requires car/engine/brakes version 1, suspensions version 1 or 2, tyres version 7 or 10, and drivetrain version 1, 2 or 3. These version gates admit the documented configuration subset, not complete schema support. Required mass, dimensions, steering ratio/lock, wheelbase, track widths, tyre dimensions, engine inertia, forward/final gear ratios and brake torque must be positive finite values. Front weight fraction is strictly between zero and one; reverse ratio must be negative. Gear count is an integer from 1 to 10. The selected compound is 0–99; its front/rear sections must exist. An absent requested compound never selects another one.

The external power LUT is recorded in RPM/Nm and must contain at least two strictly increasing nonnegative RPM coordinates covering idle through the positive limiter. Limiter must exceed idle in this subset. Turbo sections produce an explicit warning that the base table alone does not describe boosted output. Other fields are counted as uninterpreted per file. Consumed INI field sources/lines are retained. Local SDK comments were used to check units. INERTIA stores dimensions in metres, not a ready-to-use inertia tensor; TOTALMASS records configured mass without simulating fuel. The LOD_0 model reference receives only path/existence/header validation here.

## Spawn transforms and placement preflight

The KN5 reader retains each node's name, kind, active state, parent index and composed transform, including non-rendered nodes. Supported marker names are exactly AC_PIT_n, AC_START_n and AC_HOTLAP_START_0 with canonical nonnegative decimal indices. Inactive markers are omitted. A named transform and its same-named directly attached mesh at the identical inherited transform are one marker; separate duplicate markers remain errors even at identical coordinates, and that name is omitted. Noncanonical names, standalone skinned markers and invalid bases are diagnosed. Mesh-only static markers are also accepted.

Marker bases must be finite, orthogonal, unit-length and orientation-preserving within 0.001 tolerance. The source Y axis must have a world-up component greater than 0.5. Position coordinates are limited to +/-10000000 metres. Scaled, skewed, mirrored or upside-down markers are rejected, rather than repaired. Model translation and node hierarchy are applied; unvalidated model-level rotations are diagnosed and omitted. Y-up/Z-forward marker conventions were checked against the author-maintained [track construction guide](https://assettocorsamods.net/threads/build-your-first-track-basic-guide.12/). Positive X identifies the left side in the local BMW wheel nodes, so the supported vehicle footprint uses +X left, +Y up, +Z forward. No Euler conversion is used for these source bases.

For wheelbase L and configured front static weight fraction f, front footprint Z is `(1-f)*L` and rear footprint Z is `-f*L`. Left/right offsets are plus/minus half the configured axle track. The preflight applies the selected spawn basis to X/Z offsets and casts downward 20 metres from the marker plane. It returns each geometric hit and the independent `all_wheels_supported` flag, while catalog/model errors still set `has_errors`. BASEY and tyre radius are recorded but not used to solve the chassis height, spring preload or static equilibrium. This is not a body-clearance test, rigid-body solver, tyre model or playable drive.

## Independent first-drive prototype

`drive` assembles the car's first supported visual model into the track preview, sharing the existing geometry and texture budgets. It starts a paused Python simulation and a loopback controller session, with `scope: first_drive_prototype`. The static car/placement inspection commands retain their separate scopes and `simulation_ready: false` fields; those reports alone do not instantiate a running model.

The model uses four planar wheel-force patches, rather than original Assetto Corsa physics. World coordinates use +X left, +Y up and +Z forward. Each patch velocity includes body translation and yaw velocity at its configured axle/track offset. Front patches rotate by the steering angle, rate-limited to 1.2 rad/s; the maximum angle is configured steering lock divided by steering ratio. Lateral force is an original regularized slip-angle approximation with corner gain 7 per radian, using a minimum 1.5 m/s longitudinal speed in the denominator. Friction circles limit combined patch forces to the configured surface coefficient times the static normal load. Surface friction must be in the finite 0–5 prototype range.

Configured base engine torque is linearly sampled from RPM, multiplied by throttle, selected gear/final ratio and a prototype 0.9 efficiency, then divided across the driven wheels by tyre radius. A simplified rolling coupling clamps RPM to at least idle, representing assisted launch; limiter cuts drive torque. Neutral has no drive force. Braking interprets MAX_TORQUE as total torque split by front share and axle wheels, with rear handbrake torque added separately. This interpretation and assisted launch do not claim original drivetrain equivalence. Generic rolling resistance is 0.015 of normal load, and longitudinal speed-squared drag uses a prototype coefficient of 0.4 N/(m/s)^2. Low-speed braking uses bounded contact impulses to oppose patch motion and grade gravity, without an unconditional friction-free stop.

Newton force/moment sums update XZ translation and yaw with a semi-implicit fixed step of 1/120 second. Yaw inertia uses the box approximation `mass * (width^2 + length^2) / 12`, interpreting INERTIA as dimensions. Normal load uses configured front weight fraction, divided equally left/right and scaled by contact normal Y. Grade gravity is projected using the weighted contact normal. No dynamic load transfer, engine/wheel inertia, tyre rotational slip, real suspension or six-degree-of-freedom body response is solved. The force/moment structure was checked against primary [3DOF vehicle-model documentation](https://www.mathworks.com/help/vdynblks/ref/vehiclebody3dof.html); the implementation, regularization and prototype tuning are original openASC choices.

At each accepted step, four downward probes select static support below the predicted footprint. Chassis Y is the static-load-weighted mean of `ground height + tyre radius - BASEY`; the weighted geometric normal sets visual pitch/roll, with forward projected onto its plane. This is geometric attachment, not spring equilibrium or wheel/body clearance. Missing support, contact normal Y below 0.5, a vertical step over 0.35 metre, horizontal speed over 150 m/s, yaw rate over 10 rad/s, or numeric/range failure pauses at the last valid position and zeros motion. The drive command separately resolves supported static WALL geometry with the bounded upright body proxy described below. The visual car uses source hierarchy, graphics translation and a local X pitch rotation, with approximate materials; wheel steer/spin and skin textures are not animated/resolved.

Naturally aspirated RWD/FWD vehicles only are admitted. Prototype bounds are mass 50–10000 kg, wheelbase 0.5–10 m, track 0.1–6 m, tyre radius 0.05–2 m, absolute BASEY at most 2 m, steering angle 0.01–0.8 rad, and inertia width/length 0.1–20 m. Base table torque magnitude must not exceed 20000 Nm, limiter 30000 RPM, gear-ratio magnitude 100, final ratio 20, or brake/handbrake torque 100000 Nm. These numerical guards delimit this prototype; they are not original engine limits or a claim that every admitted car is compatible.

The simulation clock is independent of browser redraws and telemetry reads. Catch-up is limited to eight fixed steps per wake; discarded wall-clock backlog increments a visible lag counter. A complete input heartbeat is sent at approximately 20 Hz; expiry after 0.5 second pauses and clears controls. Window blur and tab hiding also request a pause. A local session nonce, strict JSON command fields, monotonically increasing sequence, 2048-byte body limit and same-origin Host/Origin checks constrain the input endpoint. Sequence replay is rejected. Only one controller tab is supported. These local HTTP messages are not multiplayer/network gameplay support.

## Static wall and body contact

Driving loads active near-level meshes whose names contain WALL, regardless of render visibility, during the same model read used by the ground loader. The independent `ground --walls` report also exposes this separate geometry index; vertical probes still ignore wall faces. Model/node transforms and translations follow the existing validated subset. A separate 3D BVH indexes up to 250000 input wall triangles, including subsequently discarded degenerate faces, with coordinates within +/-10000000 metres. Winding is not used to make faces one-sided. Static and moving obstacles without supported WALL naming are not included.

The drive command now requires the selected car's `collider.kn5`. The reader takes bounds of active indexed static collider vertices after node hierarchy and the same graphics offset/local X pitch convention used by the approximate vehicle renderer. Skinned, empty, flat or out-of-range colliders fail loading; there is no substitution with INERTIA dimensions. Coordinates must remain within +/-20 metres and each box half-extent within 0.01–10 metres. The result is an upright yaw-oriented box enclosing those vertices, rather than the original convex shape. Visual road pitch/roll does not rotate this prototype contact box. Auxiliary ground boxes in colliders.ini, body/ground scraping and deformable/dynamic bodies remain unsupported.

Broad-phase bounds include translation, full corner radius and body height. Narrow-phase separation uses the box face axes, triangle normal and edge cross products. Sweeps follow linear CG translation and the shortest yaw interval between fixed-step poses, with a 0.002 metre contact skin. Corner projections are linear-plus-sinusoidal curves; derivative roots divide them into monotonic intervals. The solver advances to the earliest crossing of a current separating plane, using bounded bisection on those intervals. Interior rotational extrema are included, so endpoint-only tests and near-tangent rotation are not substituted for a continuous query. Existing contacts can slide or separate when an exact swept projection proves the separating plane stays clear. Geometry concept references are the primary [dyn4j SAT explanation](https://dyn4j.org/2010/01/sat/) and [Box2D collision documentation](https://box2d.org/documentation/md_collision.html); the implementation and fixtures are original openASC code.

Contact generation clips triangles against the skin-expanded box and retains planar manifold ends. A deterministic 12-pass projected impulse solver changes XZ velocity and yaw rate. Restitution is zero; prototype tangential friction is capped at 0.35 times accumulated normal impulse. There is no positional energy bias, damage or claim of original collision tuning. The model can slide along a barrier and reverse away after stopping. Near-simultaneous triangle contacts are grouped within a 0.000001 step fraction; more than 64 manifold points or failure to converge within 80 separating-plane advances is diagnosed.

A fixed step processes at most eight contact events. When that cap is reached, remaining motion is dropped at the last nonpenetrating pose and `wall_motion_clamps` increments; simulation time still advances by the fixed step. `wall_contacts` counts contact-resolution events, not distinct crashes, and `last_wall_contact` identifies the triangle, mesh, point, normal and resolved normal impulse. Spawn overlaps fail startup. A terrain attachment that would put the box inside a wall, an almost vertical response normal, or a numeric/query limit pauses with a diagnostic. Final proxy overlap checks use a 0.000001 metre tolerance. This is bounded planar contact against static triangles, not a complete 3D rigid-body engine or guaranteed contact for all assets.
